## 一、ROV提供的外部条件

ROV 光电复合缆下水后分别进入供电舱和通信舱：

- 供电舱可以提供 48 V 直流输出；
- 通信舱内有水下交换机，可以提供以太网接口；
- 岸上与水下交换机之间通过光电复合缆中的光纤连接。

对采集模块而言，逻辑链路可以表示为：

```text
岸上电脑
   │
岸上交换机
   │
光电复合缆中的光纤
   │
水下交换机
   │
千兆双绞线
   │
采集舱内x86主机
```

只要交换机、VLAN、路由和防火墙允许互通，这条链路在上层软件看来可以近似理解为一根经过交换机延长的网线。交换机和光纤引入的正常转发延时很小，不影响 Qt 按钮控制、状态显示和远程桌面操作。

## 二、采集舱穿舱接口

采集舱后端原则上需要两个独立穿加以处理的外部通道：

1. 48 V 直流电源穿舱接口；
2. 千兆以太网穿舱接口。

这里的“开两个孔”只能理解为机械设计上预留两个安装孔，不能直接把普通电线或网线穿过孔后打胶。最终必须使用与舱体工作深度 yen容的：

- 耐压水密穿舱连接器；
- 灌封式电缆穿舱件；
- 或 ROV 厂家已有的标准水下连接器及配套尾缆。

如果设备只在甲板上连接、下水后不插拔，可以采用干插拔水密连接器；如果需要在水下插拔，则必须使用湿插拔连接器。

普通 RJ45 只能放在压力舱内部，不能作为水密和耐压边界。水密连接器后的舱内尾缆应保持 CAT5e/CAT6 的双绞结构直到 RJ45，尤其是千兆链路不能将四对双绞线长距离拆散后再随意压接。

### 2.1 千兆必须使用完整四对线

- 100BASE-TX 百兆以太网通常使用两对双绞线，共 4 芯；
- 1000BASE-T 千兆以太网使用四对双绞线，共 8 芯。

本系统不应主动选择 4 芯百兆方案。应向 ROV 方申请完整 8 芯、支持 1000BASE-T 的独立交换机端口，并确认水下交换机到岸上交换机的光纤上行也是千兆或更高。

还需确认光纤上行是否与摄像机、声呐、控制系统等设备共享，以及能为采集主机实际保留多少带宽。

## 三、48 V 供电接入方案

ROV 已经提供 48 V 直流，因此下水后不再使用陆地调试阶段的明纬 LRS-350-12 交流电源。现有 12 V 输入 DC-ATX 前面需要增加工业 DC/DC：

```text
ROV 48 V直流
    │
水密电源穿舱件
    │
保险丝＋防反接＋浪涌保护＋EMI滤波
    │
48 V→12 V工业DC/DC
    │
现有12 V输入DC-ATX
    │
主板24 pin、CPU 8 pin、PCIe采集卡、NVMe和风扇
```

另一种方案是直接选用真正支持 48 V 输入的宽压 DC-ATX，但必须验证其连续功率、输出轨能力、纹波和高温降额。

假设主机需要 200 W，DC/DC 效率为 90%，48 V 侧电流约为：

$$
I=\frac{200}{48\times0.9}\approx4.63\ \mathrm{A}
$$

若按 250 W 输出预算，则 48 V 侧约需要 5.8 A，还应考虑启动浪涌和温度降额。

必须向 ROV 方确认：

- “48 V”的实际变化范围，例如 36～60 V 或 42～54 V；
- 可长期提供的功率和电流，而不只是短时峰值；
- 输出是否隔离，负端与 ROV 船体/保护地的关系；
- 是否已有保险、浪涌和短路保护；
- 水下连接器型号、额定电流、额定水深和针脚定义；
- 激光器、水泵、阀门、TEC 与计算机是否共用该电源预算。

## 四、远程桌面运行方式

装到 ROV 后仍然可以使用 Windows 远程桌面。典型路径为：

```text
岸上Windows电脑
    │ 鼠标、键盘指令向下发送
    ▼
交换机—光纤—交换机
    ▲
    │ 压缩后的桌面变化向上传回
水下Windows 11 Pro主机＋现有Qt程序
```

远程桌面并不是持续传输未经压缩的 HDMI 原始画面。它主要向下发送鼠标、键盘等输入，向上传输经过编码的桌面和窗口变化。

当前舱内 Qt 界面不显示 8 通道波形，仅包含参数、按钮、文字、进度和状态，因此画面变化较少，远程桌面通常只占很小带宽。正式采集数据不能通过远程桌面保存，应使用独立 TCP 数据连接或先保存到舱内 NVMe。

远程桌面适合：

- 当前阶段直接操作现有 Qt 程序；
- 安装驱动和软件；
- 查看日志和设备管理器；
- 临时维护和故障排查。

远程桌面不应成为最终自动化扫描的唯一入口。网络中断或远程窗口关闭后，正在执行的扫描任务应由舱内服务继续完成或安全停止；激光急停、漏水和过温保护也不能依赖远程桌面。

## 五、远程桌面与数据传输共用一根网线

一条以太网链路可以同时承载多个连接：

```text
同一条千兆链路
├─ Windows远程桌面
├─ 扫描控制命令
├─ 设备状态与报警
├─ 每个扫描点的平均波形
└─ 断线后的文件补传
```

它们通过不同的 TCP 连接和端口进行逻辑隔离，不需要为每种业务分别布置物理网线。建议至少划分：

- 控制通道：数据量很小，优先保证及时响应；
- 状态通道：扫描进度、温度、流量、报警和心跳；
- 数据通道：平均波形与文件补传，允许排队；
- 远程桌面：只用于调试和维护。

如 ROV 交换机支持 QoS，可让控制和报警优先于大批量数据补传。但即使没有 QoS，舱内软件也应限制补传速率，避免占满共享上行。

## 六、通信带宽核算

现有采集参数为 8 通道、每通道 2000 点、16 bit、2 kHz。全部原始数据率约为：

$$
R=8\times2000\times2\ \mathrm{Byte}\times2000\ \mathrm{s^{-1}}
=64\ \mathrm{MB/s}
$$

即约 512 Mbit/s，尚未计入 TCP、以太网和自定义数据头开销。

### 6.1 百兆链路

百兆标称 100 Mbit/s，实际 TCP 有效吞吐通常约 90～95 Mbit/s，约 11 MB/s。因此百兆不能实时上传 64 MB/s 的全部原始数据。

### 6.2 千兆链路

千兆标称 1 Gbit/s，正常有效吞吐可达到约 900 Mbit/s，即约 110 MB/s量级。理论上能够承载 64 MB/s 原始数据和少量远程桌面流量，但余量还会受到 ROV 共享上行、丢包重传、程序调度和协议开销影响。

因此最终仍应采用：

- 原始数据在舱内 NVMe 落盘或缓存；
- 舱内完成多次累加平均；
- 每个扫描点完成后异步上传平均后的 8 通道波形；
- 断网时继续本地保存，恢复后补传；
- 不让网络写入阻塞 PCIe 采集线程。

若平均结果仍用 16 bit 表示，每个扫描点的数据量为：

$$
8\times2000\times2\ \mathrm{Byte}=32\ \mathrm{kB}
$$

若使用 int32 或 float32 保存平均值，则每点约 64 kB。平均累加缓冲区至少使用 int32 或 float32，不能直接用 int16 累加，以免溢出。

## 七、短期操作与长期软件架构

### 7.1 当前陆地和ROV调试

当前直接使用已有 Qt UI 程序是合适的：

1. 首先在陆地给水下主机接显示器、键盘和鼠标；
2. 使用现有 Qt 程序验证 PCIe8586M、振镜、触发、平均和 NVMe 保存；
3. 完成数小时连续采集和温升测试；
4. 接入以太网，通过远程桌面操作同一套 Qt 程序；
5. 最后接入 ROV 交换机和光纤复合缆，复测网络延时与连续性。

该阶段不应同时大改采集逻辑和网络结构，否则出现故障时难以判断是硬件、驱动、采集程序还是通信链路的问题。

### 7.2 波形放在岸上显示

舱内主机不需要绘制波形。水下侧只负责：

- 采集和平均；
- 本地缓存；
- 给每个扫描点和数据块编号；
- 上传平均波形和状态。

岸上 Qt 负责：

- 输入扫描范围、步长和平均次数；
- 下发启动、暂停、继续和停止命令；
- 接收并显示 8 通道波形；
- 显示扫描位置、进度、温度、流量和报警；
- 保存岸上副本并进行后续成像。

这样可以降低水下主机的界面负担，也使正常扫描不依赖远程桌面。

## 八、在现有 Qt 程序上增加 TCP 控制

可以在当前 Qt 程序中增加 `QTcpServer` 和 `QTcpSocket`，把岸上命令转换为启动、暂停、继续和停止操作。但不建议模拟鼠标点击，也不建议让网络代码直接调用 `on_startButton_clicked()` 之类的 UI 槽函数。

应逐步把按钮后面的实际扫描逻辑提取为独立控制对象：

```text
现有本地Qt按钮 ──────┐
                    ├─→ ScanController
岸上TCP命令解析器 ────┘       ├─→ 振镜控制
                              ├─→ PCIe采集
                              ├─→ 多次平均
                              ├─→ NVMe保存
                              └─→ 状态上报
```

建议的核心接口为：

```cpp
startScan(const ScanParameters &parameters);
pauseScan();
resumeScan();
stopScan();
```

本地按钮从 UI 读取参数后发出信号，TCP 解析器从网络报文得到相同的 `ScanParameters` 后也发出信号，两条入口最终调用同一个 `ScanController`，避免维护两套扫描逻辑。

如果 TCP 接收和采集位于不同线程，应使用 Qt 的 signal/slot 队列连接把命令送到控制对象所属线程，不要从网络工作线程直接操作界面控件或采集对象。

### 8.1 扫描状态机

舱内服务应明确维护状态，例如：

```text
Idle → Configured → Running → Paused → Running
                    │           │
                    └→ Stopping ←┘
                           │
                     Completed/Idle
```

状态机用于拒绝非法命令：

- Idle 才能启动新任务；
- Running 才能暂停；
- Paused 才能继续；
- Running 和 Paused 都可以停止；
- 正在运行时不能重复启动另一个扫描；
- 断网不能自动等价为激光继续工作，必须按预先定义的安全策略执行。

### 8.2 最终进程划分

长期可拆分为：

```text
岸上Qt控制端
├─ 参数输入与命令发送
├─ 波形和状态显示
├─ 数据校验与保存
└─ 缺失扫描点查询与补传

舱内采集服务
├─ TCP控制与状态机
├─ PCIe采集线程
├─ 平均处理线程
├─ NVMe写入线程
├─ 网络上传线程
└─ 断线缓存与任务恢复
```

远程桌面可以一直保留作为维护工具，但正式扫描由岸上 Qt 通过 TCP 控制。

## 九、操作系统选择

Ubuntu 与岸上 Windows 可以正常通过 TCP/IP 通信，操作系统不同并不会阻止网口连接。当前优先使用 Windows 11 Pro 的原因是：

- 现有 Qt 采集软件运行在 Windows；
- PCIe8586M 的现有驱动和 SDK 以 Windows 为基础；
- 振镜和激光器 USB 驱动需要优先保证兼容；
- Windows 11 Pro 可以作为微软远程桌面的被控主机。

只有确认 PCIe8586M、振镜和激光器都有成熟 Linux 驱动，并准备迁移现有软件后，才有必要评估 Ubuntu。当前不能为了操作系统偏好牺牲专业采集卡的驱动稳定性。

## 十、水冷控制与x86主机的职责边界

x86 CPU 的算力远高于单片机，但不适合直接替代全部水冷控制和安全联锁。消费主板通常没有工业 ADC、DAC、隔离数字量、大电流阀门驱动和确定性实时控制能力，Windows 启动、更新、驱动卡死或蓝屏也不能成为激光安全的单点依赖。

推荐结构为：

```text
岸上Qt
   │ Ethernet
   ▼
舱内x86 Windows主机
├─ 高速采集、平均、存储和TCP
└─ 通过隔离RS485/Modbus给定目标值
                  │
                  ▼
              MCU或小型PLC
              ├─ 温度采集
              ├─ 流量/压力/液位
              ├─ 水泵调速
              ├─ 三通阀控制
              ├─ 漏水检测
              ├─ 本地看门狗
              └─ 激光硬件联锁
```

x86 主机负责复杂任务、日志、界面和远程设定；MCU/PLC 负责毫秒级本地闭环及失联后的安全动作。激光默认应禁止，只有通信、流量、温度、漏水检测和人工允许均正常时，硬件联锁才允许出光。

三通阀能否连续调流量取决于类型：开关型只能切换水路；三线浮点型通过正反转时间改变开度；0～10 V、4～20 mA、PWM 或 RS485/Modbus 比例阀可以连续调节。阀线圈不能直接接主板或 MCU 引脚，必须通过相应驱动和隔离模块。

## 十三、网络知识点总结

### 13.1 IP地址

IP 地址用于标识网络中的主机。例如在子网掩码为 `255.255.255.0` 时：

```text
水下主机：192.168.10.50
岸上电脑：192.168.10.100
```

两台设备的地址必须不同且不能与其他 ROV 设备冲突。`.50` 没有天然的“采集主机”含义，只是网络管理员分配的设备编号。不能把岸上和水下主机设置成同一个 IP。

### 13.2 子网掩码与CIDR

子网掩码决定 IP 地址中哪些位表示网络、哪些位表示设备：

```text
IP：       192.168.10.50
掩码：     255.255.255.0
CIDR写法： 192.168.10.50/24
```

在该示例中，`192.168.10` 是网络部分，最后一段是设备部分。同一子网的设备通常可以通过交换机直接通信。

### 13.3 默认网关

默认网关是主机访问其他网段时首先交付数据的路由器地址。例如：

```text
水下主机：192.168.10.50/24
网关：    192.168.10.1
```

水下主机访问同一网段的 `192.168.10.100` 时不需要经过网关；访问其他网段或互联网时才把数据先交给网关。若 ROV 网络只有一个封闭子网，默认网关可能不是必需的；若岸上控制网和设备网分离，则必须有正确路由。

### 13.4 MAC地址、ARP和交换机

IP 用于标识目标主机，MAC 地址用于同一以太网内的实际帧转发。ARP 用于查询“某个 IPv4 地址对应哪个 MAC 地址”。交换机学习每个 MAC 地址所在的物理端口，并把后续普通单播流量只转发到目标端口。

初始 ARP 请求属于广播，交换机可能发到同一广播域的多个端口；但建立映射后的普通 TCP 单播数据不会持续发送给所有电脑。

### 13.5 交换机、路由器和光纤

- 交换机主要在同一二层网络内根据 MAC 地址转发数据；
- 路由器/网关在不同 IP 网段之间转发数据；
- 光纤只改变物理传输介质，上层仍然可以承载以太网和 IP；
- 多级交换机链路在软件看来仍可表现为一个局域网，但 VLAN、端口隔离和带宽共享会改变可达性与性能。

### 13.6 TCP和端口

IP 地址确定“哪一台主机”，TCP 端口确定“该主机上的哪个服务”，可类比为大楼地址和房间号。例如：

```text
192.168.10.50:3389  Windows远程桌面
192.168.10.50:5000  自定义扫描控制
192.168.10.50:5001  平均波形数据
192.168.10.50:5002  状态和报警
```

自定义端口只是初步规划，正式实现时应检查端口占用、配置防火墙，并把端口写入配置文件，避免硬编码分散在程序各处。

TCP 连接由源 IP、源端口、目标 IP、目标端口和协议共同区分，因此同一根网线和同一个主机 IP 可以同时运行远程桌面、控制和数据传输。

### 13.7 TCP提供什么

TCP 提供面向连接、按序、可靠的字节流，会对丢失数据进行重传。但 TCP 不知道一条业务报文从哪里开始、在哪里结束，因此自定义 Qt 协议仍需要消息头，例如：

- 魔数和协议版本；
- 消息类型；
- 负载长度；
- 任务 ID 和扫描点编号；
- 时间戳；
- 数据类型和通道数；
- CRC 或其他完整性校验。

TCP 重传可能造成延迟，因此采集线程不能同步等待网络发送完成，应通过有界异步队列和 NVMe 缓存解耦。

### 13.8 固定IP、DHCP和地址冲突

- 固定 IP 便于岸上软件和远程桌面长期找到水下主机；
- DHCP 可以自动分配地址，但地址可能变化；
- 最合理的是由 ROV 网络管理员在统一规划中给采集主机预留固定地址，或通过 DHCP 地址保留固定分配；
- 未经分配自行选择地址可能与摄像机、声呐或控制器冲突。

### 13.9 Ping能证明什么

`ping` 成功只能说明基本 IP 可达和 ICMP 未被阻止，不能证明：

- TCP 端口已开放；
- Qt 服务正在监听；
- 防火墙允许对应端口；
- 千兆吞吐足够；
- 长时间传输不会丢包或中断。

网络验收应依次测试：链路协商速率、`ping` 延迟与丢包、指定 TCP 端口连接、长时间吞吐、远程桌面，以及采集与传输同时运行时的稳定性。

### 13.10 百兆与千兆

- 百兆通常使用 4 芯，实际 TCP 吞吐约 11 MB/s，不能传输 64 MB/s 原始数据；
- 千兆使用 8 芯，实际吞吐约 110 MB/s量级，理论上可承载原始数据，但仍应保留余量；
- 链路最终速率由主板网卡、水密连接器和尾缆、水下交换机、光纤上行、岸上交换机及岸上网卡中能力最低的一环决定；
- 任意一段只支持百兆，整条端到端链路都可能协商为百兆。

### 13.11 远程桌面与正式数据通道

远程桌面传输压缩后的界面变化以及鼠标、键盘输入，适合维护；TCP 数据通道传输结构化扫描参数、状态和波形，适合自动化运行。两者可以共用物理链路，但在系统设计中必须相互独立：远程桌面关闭不应导致扫描数据丢失或安全联锁失效。
